About CipherShield

Intelligent SMS Spam and Phishing Detection Using Machine Learning — M.Sc. Cybersecurity Academic Mini-Project

Project Overview

CipherShield is a machine-learning-powered web application that analyses SMS messages and classifies them as HAM (legitimate), SPAM (unsolicited promotional) or PHISHING (deceptive messages attempting to steal sensitive information).

The system combines TF-IDF text classification with URL structural analysis to provide contextual, evidence-based predictions — without real-time internet lookups or paid threat-intelligence APIs.

How It Works
1

Dataset Loading

UCI SMSSpamCollection (original) + modern_sms_dataset.csv (supplementary synthetic) are loaded, validated, deduplicated and merged.

2

Text Preprocessing

Messages are lower-cased, URL-tokenised, phone-number-tokenised, SMS-abbreviation-expanded, punctuation-removed and stop-word-filtered.

3

TF-IDF Vectorization

Up to 8,000 unigram+bigram features are extracted. Term frequency is sublinearly scaled to reduce dominance of high-frequency words.

4

URL Feature Extraction

10 structural URL features (IP hostname, URL shortener, suspicious chars, subdomain spoofing, punycode, etc.) are appended to the TF-IDF matrix.

5

Machine Learning Classification

Three models (Naive Bayes, Logistic Regression, Calibrated SVM) are trained and compared on macro F1-score. The best model is saved.

6

Prediction & Explanation

The Flask API combines model probability scores with URL feature signals to produce a prediction, confidence score and human-readable explanation.

Spam vs Phishing — What's the Difference?
SPAM
  • Unsolicited bulk messages
  • Usually promotional or advertising
  • Annoying but rarely dangerous
  • May contain real brand links
  • No attempt to steal credentials
PHISHING
  • Deceptive, targeted messages
  • Impersonates banks, govt, delivery
  • Steals OTPs, PINs, passwords
  • Often uses suspicious URLs
  • Creates urgency or fear
Limitations
  • Phishing class relies on the supplementary synthetic dataset — real-world labelled data would improve accuracy.
  • No real-time URL reputation checking or link following.
  • Cannot verify sender identity or confirm whether a bank message is genuine.
  • Short messages with no distinctive keywords may be misclassified.
  • Model does not understand context, intent or language nuances.
  • A trusted domain in the URL does not guarantee safety — phishing sites can spoof legitimate-looking links.

Messages are classified locally. No text is sent to external servers. Only classification metadata (label, confidence, URL count) is stored in the local SQLite database when history is enabled.
